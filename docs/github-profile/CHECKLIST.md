## Private client repositories

- Keep original client repositories private and do not publish their names, screenshots, code or access links unless the client has explicitly approved it.
- GitHub can show anonymized private contribution counts, but visitors cannot see which repositories produced them.
- Use portfolio case studies and a “Request walkthrough” link as the public entry point.
- Prefer a sanitised showcase repository with fake data when a reviewer needs code evidence.
- Do not grant access from a personal-account repository solely for read-only review: personal repository collaborators receive write access. If controlled read-only access is genuinely required, use an organization repository with an appropriate role and remove access after the agreed review window.
- Even after access is removed, assume any invited reviewer may retain a local clone. Share only code you and the client are comfortable treating as disclosed.
